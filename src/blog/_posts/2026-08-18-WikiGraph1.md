# Collecting Data

In the [previous section]( {% link _posts/2026-08-18-WikiGraph0.md %} ), the biggest concern was that because we needed to interact with Wikipedia's servers, the amount of requests needed to be minimized. Fortunately, there are some ways to get [data dumps](https://en.wikipedia.org/w/index.php?title=Wikipedia:Database_download&oldid=1362585910#Where_do_I_get_the_dumps?)[^1].

## MediaWiki Content File Exports

Within all of the options present, there is a directory called <code class="langauge-plaintext"><a href="https://dumps.wikimedia.org/other/mediawiki_content_current/enwiki/">enwiki/</a></code>. Which should contain all of the articles we are looking for (as well as some other stuff). As of writing this, the latest dump is from August 2026. All of these files are offered in an XML format.

# Understanding the Data

## What is XML

XML is a markup language which has a similar structure to HTML. It's sole goal is to provide a way to transport data in an software/hardware independent format. W3Schools provides [examples](https://www.w3schools.com/xml/xml_usedfor.asp) of what this data looks like. What the data is trying to represent is indutive enough to not need explaining.

```xml
<!-- From https://www.w3schools.com/xml/xml_usedfor.asp (truncated) -->
<?xml version="1.0" encoding="UTF-8"?>
<bookstore>

  <book category="cooking">
    <title lang="en">Everyday Italian</title>
    <author>Giada De Laurentiis</author>
    <year>2005</year>
    <price>30.00</price>
  </book>

  <book category="children">
    <title lang="en">Harry Potter</title>
    <author>J K. Rowling</author>
    <year>2005</year>
    <price>29.99</price>
  </book>

  <!-- Truncated -->

</bookstore>
```

## XML as a Database

Because XMl files are effectively a document database, a useful way to understand their structure is to rely on their [XML Schema](https://www.w3schools.com/xml/schema_intro.asp). `enwiki` exported files each rely on the same schema file which can be found [online](https://www.mediawiki.org/xml/export-0.11.xsd).

## Potential XML Challenges

Because of the XML syntax rules, some characters might not usable. This could include:

- Characters that cannot be used in HTML such as '&', which needs to translated to `&amp;`. This might be an issue, especially if an article title uses these characters.
- Character encoding might be an issue. The extent of this issue will be evaluated when it arises.

# The Current Goal

Now that the archive data is known, the goal now is to:

1. Iterate over every single XML file given in the archive, filtering out everything that isn't an article.
2. For each article we iterate over: 
   1. Extract all article text and parse out every link. MediaWiki, the underlying software used by Wikipedia, provides [documentation](https://www.mediawiki.org/wiki/Help:Links) on how links are formatted.
   2. Store all links inside of a database for later stages. This will be important to quickly generate the graph file (or whatever will be used in the end visualization tool).
  
# Considerations

The biggest challenge generating the link database will be that each XML file is too large to fit into memory[^2] and needs to be streamed. While Go does provide [an easy way to parse and XML file](https://pkg.go.dev/encoding/xml#Unmarshal), it requires the entire file to be loaded in at once. A much more [streamable package](https://pkg.go.dev/iter) will need to be used in addition to lower level XML decoding operations.
